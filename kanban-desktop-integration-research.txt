HERMES DESKTOP APP — KANBAN INTEGRATION RESEARCH
==================================================
Date: 2026-06-04
Status: Feasibility confirmed, implementation not started

EXECUTIVE SUMMARY
-----------------
The kanban board UI exists only in the web dashboard plugin. The desktop
Electron app has no kanban panel — only a /kanban slash command that sends
text to the agent. Integration is architecturally straightforward: the
desktop app uses lazy-loaded React views, and the kanban backend already
exposes a clean REST+WebSocket API at /api/plugins/kanban/.

KANBAN API ENDPOINTS (all under /api/plugins/kanban/)
-----------------------------------------------------
GET    /board                    — Full board grouped by status columns
GET    /tasks/{task_id}          — Single task detail
POST   /tasks                    — Create task
PATCH  /tasks/{task_id}          — Update task (move, edit, assign)
DELETE /tasks/{task_id}          — Delete task
POST   /tasks/{task_id}/comments — Add comment
GET    /tasks/{task_id}/attachments — List attachments
POST   /tasks/{task_id}/attachments — Upload attachment
GET    /attachments/{id}         — Download attachment
DELETE /attachments/{id}         — Remove attachment
GET    /diagnostics              — Task diagnostics
WS     /events                   — Live task event stream

Board columns (in order):
  triage, todo, scheduled, ready, running, blocked, review, done

KEY ARCHITECTURE NOTES
----------------------
- Desktop app uses window.hermesDesktop.api() for all HTTP calls
- API calls go through the gateway backend (same process as dashboard)
- Auth is session-token based (injected via window.__HERMES_SESSION_TOKEN__)
- The kanban plugin API uses the same auth middleware as core API routes
- WebSocket for live updates needs session token as ?token= query param
- The kanban backend is already mounted when the gateway runs
